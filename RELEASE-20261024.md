## Changes Since The October 18 Source Release

- Independent Home Motion dispatch and FIFO-preserving native recovery remain
  separate from ordinary server admission. Home work does not justify bypassing
  the server's RAM gate or counting an untracked server encode as Home work.
- Updated exact callback contracts keep all 15 reviewed Home callback types,
  including three SigLIP callbacks, connected to the current native bundle.
- Chunk polling no longer transparently resubmits into the same exhausted Home
  scope. A qualifying terminal Home-admission failure can recover once through
  counted native admission after the old Home lease has unwound. Only the remote
  checkpoint is cleared; payload, audio and timing are preserved.
- Non-chunk resubmission requires valid ownership and sufficient original poll
  budget. Expired polls cancel their exact nonterminal remote. The worker also
  checks cancellation while waiting without progress and awaits owned cleanup.
  An acknowledgment is not proof that process cleanup has finished.
- Native Packaging improvements are preserved alongside real-person thumbnail
  identity. Five old interventions remain retired: wordSync persistence,
  B-roll final-checkpoint compatibility, volatile B-roll input hashing, empty
  temporary-directory age protection and the extra FX marker injection.
- Retained Home media/camera/scene/Map/Motion integrations, Custom controls,
  render admission, memory fairness, priority and long-assembly fixes are bundled.

Finite deadlines remain. This does not promise that every provider, encoder or
arbitrary future task can never time out. Real failures are not hidden in an
unlimited retry loop. Codec, frame-rate, quality and licensing contracts remain.

## Build And Verify

Use a builder with the pinned stock image available and your own registry access
where required. The build needs no production volumes or secrets.

```sh
docker build --pull=false --network=none -t local/vidforge-custom:20261024-source .
python3 update-tools/verify_image.py local/vidforge-custom:20261024-source \
  --expected-version 2026.10.22.12 --docker-context default
```

Select your actual Docker context deliberately. Verification requires host Node
22 (or the reviewed compatible runtime), Python 3 and Docker. The mandatory
`vf-custom-41-20261023` gate checks 41 hooks; additional build steps verify the
exact Home and SigLIP callbacks. Never disable a gate to accept changed upstream
code. An image built from sanitized source has its own ID, not the private
production image ID.

Focused regressions can run in a disposable image container:

```sh
docker run --rm --network=none -e VF_MODS_BOOTSTRAP=0 \
  -e NODE_PATH=/app/node_modules --entrypoint=node \
  local/vidforge-custom:20261024-source --test \
  /opt/vf-custom/tests/home-chunk-recovery.test.cjs \
  /opt/vf-custom/tests/native-chunk-recovery.test.cjs \
  /opt/vf-custom/tests/fflow-resubmit.test.cjs \
  /opt/vf-custom/tests/home-callbacks-update.test.mjs \
  /opt/vf-custom/tests/home-siglip-update.test.mjs \
  /opt/vf-custom/tests/home-motion-dispatch.test.cjs \
  /opt/vf-custom/tests/home-motion-recovery-order.test.cjs
docker run --rm --network=none --entrypoint=python3 \
  local/vidforge-custom:20261024-source -B -m unittest discover \
  -s /opt/vf-custom/tests -p test_home_process_admission.py
```

The package includes narrow reviewed callback/chunk fixtures required by these
gates and regressions. Full private upstream bundle copies, operational scripts,
settings, job inventories, database backups and credentials are excluded.
Some older hardware/native-engine tests require the recipient's own extracted
licensed engines; the focused tests above do not certify their hardware.

## Install Safely

1. Back up your effective settings, Compose, consistent database and media;
   retain a known-good rollback image. Keep all secrets private.
2. Build, verify and cold-start with isolated temporary data and no production
   mounts or provider access. Confirm health and all runtime hooks.
3. In an authorized quiet window, change only VidForge's image reference and
   recreate only that service. Preserve its volumes, network and credentials.
4. Verify native version, settings, original job inputs/checkpoints, actual
   progress and small media samples. Do not cancel/requeue entire videos to
   test this. A code rollback must not overwrite newer database progress.

## Optional Home PC

Home worker integration needs your own companion runtime, licensed engine
extractions, authenticated tunnel, paths, credentials and compatible hardware.
This source release does not install or connect another person's Home PC.
Use the helper documentation under `home-graphics-worker/` and the existing
release guide `RELEASE-20261018.md` for companion boundaries.

Preserve your own working capacities, transfer limits and RAM settings; the
origin installation's CPU18/GPU14/SigLIP20/dispatch40 are not universal defaults
or proof that 14 concurrent NVENC sessions are supported on every GPU. Without
a Home PC, keep Home-only options disabled and use native rendering.

Scene GPU mode means NVDEC decoding plus CPU scene analysis, not pure GPU work
and not reduced output-video quality. CPU/GPU busy counts are not completion
proof. GPU decode with original x264 and actual NVENC encoding are distinct
paths; verify the worker mode and successful artifacts on your own system.
Always retain bounded, counted native fallback when Home is unavailable.
