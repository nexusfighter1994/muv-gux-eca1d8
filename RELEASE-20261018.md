# VidForge Custom Overlay: Home Media Dispatch

This repository contains the custom source overlay, not a production database,
activated license, provider credentials, or a Docker image download. Build it on
the pinned stock base in `Dockerfile`; keep your own configuration and volumes.

## Latest Changes

- Exact native composition overlays and mirror commands can use the Home queue.
- The media bridge now also recognizes the reviewed single-overlay blur/fade
  composition. Both JavaScript and Python independently validate its exact
  command shape, bounded timing, input paths and compatible source stream.
- The original filter graph, audio-copy behavior and timeline are preserved.
  Encoding uses the existing `nvenc-high-qp14-v1` policy. This does not lower
  quality settings or enable arbitrary filter graphs.
- Busy, offline, unsupported and unverified Home results use the existing
  counted native recovery. A CPU-recovered result is not reported as GPU output.
- Hot-upgrade v2 preserves the scheduler and in-flight work, without installing
  duplicate recovery permits. The regular installer also applies this after a
  fresh container start.
- Home dispatch can now be configured independently from encoder concurrency.
  An optional `/data/runtime/pc-home-dispatch-limit.json` containing
  `{"slots":40}` permits up to 40 in-flight Home assignments. Missing, zero or
  invalid settings retain automatic CPU-plus-available-GPU capacity. Valid
  explicit limits are 1-50. Offline/stale health still stops new assignments;
  in-flight scopes, native recovery limits and RAM admission are unchanged.
  This file is site configuration in the persistent data volume, not a bundled
  preset. It reloads within one second. GPU concurrency remains a separate
  setting in `/custom`; the dispatch override has no new UI control yet.

The snapshot also includes the current scheduler, Home capability/queue,
SigLIP, motion/Map and duration-timeout modules. This release does not change the
native RAM gate, automatically increase server limits, or modify other services.

## Qualification And Limits

- New media tests: 35 related Node tests, 10 Python CLI/recipe tests and one
  installer test passed in the authoring environment.
- Actual GPU blur/alpha-overlay fixture: H.264 High, 1920x1080, yuv420p, 24 fps,
  timebase 1/12288, zero start, unchanged copied audio, SSIM 0.997483 against the
  CPU reference. CPU-GPU-CPU decoding passed.
- A separate real production CPU-GPU-CPU join retained all 2,113 decoded frame
  hashes. Remuxing corrected DTS at transitions; presentation-time deviation
  stayed below one frame. This is not a guarantee for all inputs or hardware.
- The new blur path is hot-enabled, but a production completion on that newly
  added path had not yet been observed at the initial release check.
- Full `smooth_transform` image rendering, arbitrary multilayer graphs,
  contact sheets and CRF16 slow-to-fit are not newly enabled by this bridge.
- Home GPU capacity is a site-specific setting, not a bundled preset. Fourteen
  logical slots were configured at the originating site, but fourteen concurrent
  NVENC sessions are not certified. Recoverable encoder failures were observed.
  Do not copy that capacity without checking your GPU, driver and memory budget.
- Independent dispatch, queue and pool-claim regression tests: 25 passed.

## Build And Deploy

The prepared originating-site candidate is
`local/vidforge-custom:20261018-63-home-dispatch`. That tag is local, not a public
registry image. It extends image62 with independent dispatch configuration.
The mandatory image contract and isolated startup must pass before deployment;
the production container is not recreated by preparing or sharing this source.

1. Back up the current image reference, custom source, configuration and data.
   Wait for a suitable deployment window; do not interrupt active renders.
2. Build a new, uniquely named candidate from this checkout:

   ```sh
   docker build --pull=false --network=none -t vidforge-custom:home-media-20261018 .
   python3 update-tools/verify_image.py vidforge-custom:home-media-20261018 --expected-version 2026.10.13.7 --node /path/to/node
   ```

   The pinned base must already be present locally or fetched through your
   normal authorized registry access. Do not substitute an unverified latest
   base to bypass a failed hook check. The current contract is 40 required
   hooks; older historical sections of `update-tools/README.md` mention 34.
3. Rehearse startup with an isolated empty data volume and no network. Check
   health, the installed media hook, CLI import and the exact recipe fixture.
4. Use your existing deployment configuration with only the verified image
   reference changed. Keep existing volumes, credentials and provider settings.
   Recreate only when authorized and current work is protected.
5. Check API/worker health and a real completion. Validate stream settings,
   copied audio and mixed CPU/GPU joins on your own hardware. Keep the previous
   image for rollback; never restore a stale whole database over newer work.

Home offload requires a separately installed compatible authenticated Home
worker/tunnel and the site's own secret files. These private runtime files are
not included. Without it, keep Home-only features disabled and use native
rendering. Never expose an unauthenticated worker publicly.

Focused checks from the checkout:

```sh
node --test tests/home-media.test.mjs tests/home-media-recipes.test.mjs tests/home-queue.test.mjs
python3 -m unittest discover -s tests -p 'test_node_media*.py'
python3 -m unittest discover -s tests -p test_home_media_install.py
```

Some older tests require private/upstream fixtures deliberately excluded from
this public export. Do not confuse missing optional test fixtures with permission
to skip the mandatory image verifier.
